# Desktop distribution

The supported npm install uses `bin/ghostless.cjs`, a Node launcher that finds Python 3.11+ and runs `python -m ghostless` from the packaged `lib/` directory. It needs no Bash on macOS, Windows, or Linux. Set `GHOSTLESS_PYTHON` to select a specific interpreter. The Python wheel's console entry point remains available for the voice commands, but the npm package is the supported way to get the packaged skills.

`ghostless install-skills` links skills on macOS and Linux and copies them on Windows. A one-off npx/pnpm package also copies skills, because cache cleanup would break links into the temporary package. The installer leaves foreign skill paths alone unless `--force` is supplied. It also writes a stable launcher at `~/.local/bin/ghostless` on macOS and Linux, or `%USERPROFILE%\.local\bin\ghostless.cmd` on Windows, unless `--no-launcher` is set or the run is a one-off npx/pnpm copy. That launcher reads `~/.ghostless/suite-root` and keeps `ghostless` available after a Node version change removes the version-scoped npm bin. It will not replace a command it did not install. If the recorded suite is gone, it names that path and the reinstall command.

`ghostless update` upgrades a global npm install and refreshes its skills. For a checkout, update Git and rerun `ghostless install-skills --force`. For a one-off install, rerun `npx --yes ghostless@latest install-skills --force`. `ghostless reset` removes owned skill links/copies; `ghostless uninstall` also removes `~/.ghostless/`. Remove the global npm package separately with `npm uninstall -g ghostless`. Voice projects are separate and are not removed.

The npm artifact is packed, installed in a temporary prefix, and exercised by `tests/smoke_package.py` on macOS, Windows, and Linux in `.github/workflows/package.yml`. The smoke checks the installed launcher, skill installation, project initialization, build, learn, edit sessions, and judge. It runs from outside the checkout.

The Rune editor in [`editor/`](../editor/) is not part of the npm package and is not included in the npm tarball (see [docs/EDITOR.md](EDITOR.md)). Build it from a Git checkout. The `start`/`finish` session workflow and the editor share the CLI's UTF-8, project-relative session files (see `SCHEMA.md`). `ghostless edit` and `ghostless sessions --open` launch the built editor, which resolves the project the same way as the CLI. `tests/smoke_editor.py` builds the editor and drives a full edit session on macOS, Windows, and Linux in `.github/workflows/editor.yml`, and `tests/smoke_package.py` exercises `start`/`snapshot`/`finish` through the packed npm CLI. Signed or otherwise straightforward desktop installers remain the distribution follow-up. The [Rune editor workflow](../.github/workflows/editor.yml) uploads a per-OS binary on every push, and those binaries are not release assets. Nothing open tracks installing them: [#13](https://github.com/hirefrank/ghostless/issues/13) closed with the cross-platform CLI, and [#9](https://github.com/hirefrank/ghostless/issues/9) closed with the editor itself.
